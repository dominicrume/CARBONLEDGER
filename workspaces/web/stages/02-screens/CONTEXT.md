# web / 02-screens: Build or change a screen

## Input
A flow in docs/ux/FLOWS.md

## Process
Follow rules/ENGINEERING.md. Work in small steps. Write the failing test or vector first, then the change.
Record any real decision in docs/DECISIONS.md.

## Output
The screen, wired to the API, with failure states

## Completion
Every failure says what happened and that nothing was recorded.

## Do not
Never put a key, a secret or a decision into the browser.
